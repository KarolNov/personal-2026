blueprint is how I work on larger, architected changes with agents. It sits between
[wayfinder](https://github.com/mattpocock/skills) and [OpenSpec](https://github.com/Fission-AI/OpenSpec): you bring
the solution, and it grills *that* solution in a few short rounds instead of hunting for alternatives. Then it writes
the change up where your team already keeps docs, builds it task by task, and keeps the specs and the code honest in
both directions. It lives in my [skills repo](https://github.com/KarolNov/skills) with the other Claude Code skills I
use daily.

## How it works

- **`/blueprint-setup`** looks at where you already track projects and tickets, picks where specs and blueprints live,
  and maps the repo's capabilities to code.
- **`/blueprint <your solution>`** plays it back, sketches it, grills it, and writes a blueprint as two linked
  documents: a plain-text **brief** for agents (decisions, spec delta, tasks) and a visual **review** for people.
- **`/blueprint apply`** builds it task by task, checks each requirement against the code, then folds the change into
  the capability specs.
- **`/blueprint-drift`** and **`/blueprint-sync`** catch the two ways specs and code drift apart: the code strayed from
  the spec, or the spec fell behind the code.

## Reviews people actually read

Every review opens with a before → after diagram with the change coloured in. For behaviour over time, like retries,
offline or ordering, it offers a **playground**: a small interactive model with scenario buttons, knobs and a switch
that runs the same scenario through the old and the new design.

Specs and blueprints can live in Notion (the default), Obsidian, Linear, Jira and Confluence, GitHub or a Markdown
folder, with tickets wherever the team keeps them. The only thing in the repo is a small `.blueprint/` folder that
maps capabilities to code and lets `drift.py` tell from git alone which specs need another look.

## See it in use

The [skills repo](https://github.com/KarolNov/skills) runs blueprint on itself: its `.blueprint/` folder, the drift
check on every pull request, and the [specs and blueprints](https://app.notion.com/p/karolnov/Specs-blueprints-41c43cce21f2819ba9e9e27bc322d312)
it writes. [jambo](https://github.com/KarolNov/jambo) runs it too, on a real app with sync, audio and AI agents, with
its own [specs and blueprints](https://app.notion.com/p/karolnov/Specs-blueprints-41b43cce21f281a8aedffc816ffb7b69).
Both Notion workspaces are public and read-only.
